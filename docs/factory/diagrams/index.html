One thread. Many contributors. One outcome.

Proposed experience: one outcome can combine code, research, diagrams, and documents. Simple requests can skip decomposition.

Dashed bidirectional links are addressed peer messages. Independent tasks join into an evidence-bearing result. Completion, acceptance, delivery, and settlement are separate; settlement is reversible.

Reasoning plans; durable services execute.

Proposed Factory composition on T3 V2: models propose plans; durable services validate transitions and run accepted work.

Task dependencies are distinct from execution lineage. V2 means the existing command/event/outbox engine. Peer discussion does not change ownership or acceptance; typed service commands do.

Place the work; preserve its owner.

Proposed shared placement and admission: harness/model, target environment, and provisioning are separate choices.

Sandbox candidates share one category: Blaxel, Modal, Daytona, E2B, Baseten, and others. Capabilities differ; batch jobs are optional. Provisioning does not transfer ownership. Persist artifacts and reconcile uncertain attempts before retrying.

A repeatable way to settle work.

Proposed workflows reuse outcome threads and tasks. Manual, scheduled, and scoped event requests enter the same bounded execution loop.

Filter and deduplicate events before model work. Dependency readiness drives parallel execution; phase names are presentation. Record explicit attempts or plan revisions for failures and new findings. No-op events stay quiet.

Every thread can orchestrate. One optional project role.

Proposed UX: outcome threads can start directly. One ordinary thread may be designated to coordinate priorities and shared decisions for an explicit project scope.

Dashed arrows mean optional coordination, not a prerequisite to launch an outcome. The current create/resume binding is checkout-local; arbitrary existing-thread assignment and revision-checked reassignment are proposed. Reassignment preserves active attempts. A role grants no extra authority.
